[0] 이 문서를 다시 작성하게 된 경위 (중요)
------------------------------------------------------------
이 문서의 이전 버전은 "학습 코드가 LogisticRegression에서 LightGBM으로
교체되었다"는 내용을 담고 있었으나, 이는 실제로 반영된 변경 사항이
아니라 작업 중 제안/실험 목적으로 작성되었던 별도 코드였음이
확인되었음.

실제 운영 중인 학습 코드(사용자가 캡처로 공유)는 처음부터 지금까지
TF-IDF(단어 단위) + LogisticRegression 그대로이며, 변경된 적 없음.

이에 따라 아래 세 파일을 실제 코드 기준으로 정정함.
  - script_1.1.1.py : 실제 학습 코드로 전체 교체
  - script.py        : MODEL_PATH를 tfidf_logreg.pkl로 원복
  - README.md        : LightGBM/문자 n-gram 등 미채택 내용을
                        "검토만 된 제안 사항"으로 명확히 재분류

다음 담당자는 본 문서의 [0]~[6]을 실제 상태로 신뢰하고,
혹시 과거 대화나 문서에서 LightGBM/문자 n-gram/언어별 F1 구현 등을
"이미 반영된 것"으로 언급하는 내용을 보게 되면 그건 오기였다고
간주할 것.


[1] 프로젝트 개요
------------------------------------------------------------
AI 코딩 에이전트가 대화 도중 특정 시점에서 다음에 취할 행동(action)을
14개 클래스 중 하나로 예측하는 문제.

데이터: train.jsonl(70,000건) + train_labels.csv
평가: macro F1 (14개 클래스, ALL_CLASSES 리스트로 코드에 명시됨)

14개 클래스:
  read_file, grep_search, list_directory, glob_pattern,
  edit_file, write_file, apply_patch,
  run_bash, run_tests, lint_or_typecheck,
  ask_user, plan_task, web_search, respond_only


[2] 실제 코드 구조 (현재는 script_full.py의 train() 함수)
------------------------------------------------------------
※ 2026-07-05: 아래 로직은 원래 script_1.1.1.py에 있었으나,
  script.py(추론)와 통합되어 현재는 script_full.py의 train() 함수로
  이동함. 로직 자체는 변경 없이 그대로 옮김.

1) import 및 상수
   - csv, json, os, joblib
   - sklearn: TfidfVectorizer, LogisticRegression, Pipeline,
     train_test_split, f1_score
   - ALL_CLASSES: 14개 클래스 리스트 (Macro-F1 계산용으로 import됨)

2) 데이터 로드
   - train.jsonl 한 줄씩 json.loads → samples
   - train_labels.csv → {id: action} 딕셔너리(labels)
   - X = [s["current_prompt"] for s in samples]
   - y = [labels[s["id"]] for s in samples]

3) train/val 분할
   - train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
   - 변수명은 X_train/X_val/y_train/y_val (test가 아니라 val로 명명됨에 유의)

4) 파이프라인 정의
   - TfidfVectorizer(ngram_range=(1,2), min_df=2, max_features=80_000,
     sublinear_tf=True, lowercase=True)
   - LogisticRegression(max_iter=500, class_weight="balanced", C=2.0)

5) 1차 학습
   - pipe.fit(X_train, y_train)  (train 80%만 사용)
   - print("학습 완료")

6) val 평가 (2026-07-05 사용자 제공 캡처로 확인 및 반영 완료)
   - val_pred = pipe.predict(X_val)
   - macro_f1 = f1_score(y_val, val_pred, labels=ALL_CLASSES,
     average="macro", zero_division=0)
   - print(f"Validation Macro-F1: {macro_f1:.4f}")
   - ※ 이전 버전 문서에서 "미확인 구간"으로 표시했던 부분이며,
     이제 실제 코드가 확인되어 script_full.py에 반영됨

7) 전체 데이터 재학습
   - pipe.fit(X, y)  ← train/val 구분 없이 전체 100% 데이터로 다시 학습
   - 주석: "전체 학습 데이터로 재학습"

8) 저장
   - os.makedirs("./model", exist_ok=True)
   - joblib.dump(pipe, "./model/tfidf_logreg.pkl", compress=3)

9) [신규] 추론까지 이어서 실행 (infer() 함수)
   - train()이 반환한 pipe 객체를 그대로 받아 test.jsonl 예측
   - .pkl을 디스크에서 다시 읽지 않고 메모리의 pipe를 바로 사용
   - sample_submission.csv 형식에 맞춰 output/submission.csv 생성

** 중요 포인트: 5)에서 학습한 모델과 7)~8)에서 저장하는 모델은
   서로 다른 모델임 (5)는 train 80%만, 7)은 전체 100%로 학습).
   6)에서 확인하는 Macro-F1은 5)번 모델 기준이며, 실제 저장/추론에
   쓰이는 7)번 모델의 성능을 그대로 보장하지 않음 (일반적으로는
   데이터가 늘어나므로 비슷하거나 더 나을 가능성이 높지만,
   별도로 검증된 사실은 아님).


[3] 파일 통합 — script_1.1.1.py + script.py → script_full.py
------------------------------------------------------------
경위:
  - 기존에는 학습(script_1.1.1.py)과 추론(script.py)이 별개 파일로
    분리되어 있었음
  - 사용자 요청으로 두 파일을 하나로 병합 (script_full.py)
  - 병합 시 로직 변경 없음 — train()/infer() 함수로만 구분해 재배치
  - infer()는 디스크의 .pkl을 다시 읽지 않고, train()이 반환한
    pipe 객체를 그대로 사용 (같은 프로세스 내 실행이므로)

과거 정정 이력 (참고용):
  - script.py의 MODEL_PATH가 한때 "학습 코드가 LightGBM으로
    바뀌었다"는 잘못된 판단으로 tfidf_lgbm.pkl로 수정되었던 적 있음
  - 이후 실제 학습 코드가 LogisticRegression 그대로임이 확인되어
    tfidf_logreg.pkl로 원복됨
  - script_full.py는 이 원복된 상태(tfidf_logreg.pkl)를 기준으로
    작성됨

레거시 파일 처리:
  - script_1.1.1.py, script.py는 삭제하지 않고 보관 중이나 미사용
  - 다음 담당자는 script_full.py 하나만 실행하면 됨


[4] 확인이 필요한 사항 (다음 담당자 확인 요망)
------------------------------------------------------------
1) 언어별(ko/en/mixed) 성능 확인 여부
   - session_meta.language_pref 필드가 데이터에 존재하나,

2) 실제 baseline 수치 미기록
   - script_full.py의 Macro-F1 출력 코드는 확인/반영되었으나,
     실제로 실행해서 나온 수치 자체는 아직 본 문서에 기록되지 않음
   - 최초 실행 후 아래 [5]에 반드시 기록할 것

[6] 다음 담당자를 위한 제안 순서
------------------------------------------------------------
1. script_full.py를 실행해 Validation Macro-F1을 확인하고 [5]에 기록
2. session_meta.language_pref 기준으로 언어별 macro F1을 나눠서 확인
   (혼합 문장 그룹의 성능 저하 여부 우선 확인)
3. 위 수치를 기준으로 아래 개선안들을 "채택 여부 실험" 형태로 하나씩 검증
   - 문자(char) n-gram 병행 (혼합 문장 대응)
   - session_meta / workspace 구조화 피처 추가
   - history 파생 피처(직전 action 등) 추가
   - LogisticRegression 대비 다른 분류기(LightGBM 등) 비교
4. 성능 개선이 실제로 확인된 항목만 채택 (임의로 알고리즘을
   교체하지 말고, 반드시 baseline과의 비교 수치를 남길 것)
5. 이후 Stage 2(multilingual MiniLM) 및 ONNX 변환+양자화는
   Stage 1 개선이 한계에 도달했다고 판단될 때 검토
